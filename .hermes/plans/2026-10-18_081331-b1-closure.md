## W2: 인간·서비스 권한 증명 보완 후 교차 프로세스 경합
- 단순 시험 추가 단계가 아니라 초기 admission/hold acceptance/continuation claim/각 신규 stage의 권한 계약을 일치시키는 구현 단계다.
- 역사 receipt를 재작성하지 않고 별도 immutable authority binding으로 acceptance의 scope/source/grant revision을 결속한다. revoke→regrant ABA로 옛 acceptance를 새 실행 허가로 사용하지 않는다. 새 복구 허가는 기존 결정 보존과 별개 증거다.
- continuation의 인간 현재 권한과 별도 DriveReview 서비스 권한을 신규 실행 transaction 안에서 검사한다. CommitPass/CommitFail/Abort 등 외부 stage 없는 결정 처리와 신규 외부 실행의 권한 요구를 혼동하지 않는다.
- 서비스 revoke 후 재허용 시 옛 bearer가 재인증으로 살아나는 반례를 먼저 시험한다. 권고는 revoke에서 verifier를 무효화하고 명시적 재발급을 요구하는 것. 단순 context revision 거부로 credential 부활 금지를 대신하지 않는다.
- 각 요청/페이지 저장/신규 stage의 시각을 주입 가능한 clock으로 공급해 만료 경계를 시험한다. cfg.now 시각 정책 변경은 명시적 계약으로 기록하고 암묵 변경 금지.
- recovery_required 기록과 실제 권한 있는 복구 소비부를 구분한다. 외부 효과가 불명인데 lease 갱신만으로 다시 실행하지 않는다.
- 경합 매트릭스: 인간 revoke/disable→acceptance, acceptance→revoke→continuation, service revoke/rebind/expiry→stage-start, stage-start→revoke→result/session 저장→다음 stage 거부, revoke→regrant/rotation, worker 재배정→옛 결과 거부, start→crash→재개방.
- 각 순서는 두 실제 프로세스 pipe/barrier/marker로 증명. 자식 시험 0개 선택은 실패. Err뿐 아니라 S1/token/outcome/hold/progress/stage/session/claim/backlog 무변경 또는 의도된 변경을 단언한다. 이미 시작한 stage 결과/session은 보존하되 stale fence의 쓰기는 거부한다.

## W3: artifact 실제 소비부
- 선행 W1/W2. caller 경로 대신 order/tuple에 결속된 artifact ID로 해결한다.
- 현재 ReadArtifact·immutable provenance 검사, own 읽기 성공과 foreign/path traversal/symlink/변조 거부. disabled/retired source의 역사 읽기는 승인된 현재 read grant 정책을 따르며 일괄 enabled 조건으로 막지 않는다.

## W4: publish는 별도 durable effect 계약
- 선행 W2/W3. scoped mode에서 기존 authorize helper가 거부되고 line ProductProjection helper만으로 durable start/outcome이 생기지 않는다는 관찰을 구현 전 재대조한다.
- 기존 GithubPublisher의 opaque key issue/operation attempt 파싱, attempt=1 fallback, 기존 workdir 의존, push 후 open-PR 조회 및 응답 손실 Retryable 처리를 새 계약과 대조한다. 곧바로 제품 포트에 꽂지 않는다.
- request identity에 principal 및 revision, source instance, order/lifecycle/attempt/run/generation, approval receipt, tuple/artifact digest, 대상 repo/base/head를 결속한다.
- 현재 PublishApproved 및 필요한 service 권한 검사와 durable start는 동일 SQLite write transaction. 외부 호출은 commit 이후. 결과 저장은 수락된 효과/fence에 결속하고 신규 retry 권한과 분리한다.
- unknown/crash/응답 손실은 내구 복구 상태. reconciliation은 repository/head SHA/base/operation 결속을 확인하고 open PR 하나 또는 open PR 부재만으로 성공/재시도를 판정하지 않는다. 닫힌 PR도 반례에 포함한다.
- 원격 exactly-once 보장이라고 표현하지 않는다. 모의 port 호출/실제 제품 HTTP·CLI/실 GitHub는 별도 증거다.

## W5: 감사 원천 및 export coverage
- 필수 연결 제안: S1+intake provenance; 제품 S4 hold/stage/result/session; S6 tuple/promotion; product approval/grant/token/outcome; scope/service 변경·복구; S5 durable publish start/result. 원격 확인 증거는 로컬 publish 기록과 구분한다.
- S2/S3/governance/casting 및 M6는 실제 적용 경로·저장소·adapter를 조사한다. M6와 governance를 동일시하지 않는다. 비적용/미연결/유예를 각각 표시하고 유예는 승인 전까지 미완으로 남긴다.
- service가 A→B로 바뀌어도 과거 A 변경 이벤트를 현재 B grant로 재분류하지 않도록 이벤트 당시 source scope의 불변 증거를 저장한다.
- export MUST: 첫 100 주문은 전체 export가 아님을 DTO/문서에 표시, 권한 있는 집합의 has_more·coverage/cutoff 제공, 선택 주문 전체 이력으로 응답 바이트가 무제한임을 명시. 전체 원장 검증 시간 및 숨겨진 손상에 따른 타 사용자 응답 실패 결합도 기록. 선택 행만 검증하는 완화 금지.
- cursor·응답 예산·검증 비용 개선은 정책 결정 제안. 자원 수치는 실측/기존 예산 근거 없이 정하지 않는다. 현재 절충을 영구 유예 승인으로 취급하지 않는다.
- 제품 서버 인수는 W0 P1/P2를 각각 검증하고 실제 issue→PR 통합이라 보고하지 않는다.
