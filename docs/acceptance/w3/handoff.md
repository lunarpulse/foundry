## 제품 호출과 권한

* `serve --product`의 실행 프로필은 기존 v4 DB, `product-pack-pins`, `FOUNDRY_W3_IMAGE=sha256:<64 lowercase hex>`, 한 개의 절대 `FOUNDRY_REVIEW_PACK`, `FOUNDRY_REPO_PATH`, 서로 분리한 `FOUNDRY_PRODUCT_{ARTIFACT,SESSION,CLAIM}_ROOT`를 사용한다. 기존 설치·DB ID, review source 및 source commit 설정이 적용된다. `FOUNDRY_DIE_TIMEOUT`은 1–3600초이며 미설정 시 600초다. 로컬 Docker 접점은 `unix:///var/run/docker.sock`으로 고정했다. 제품 serve에서 `FOUNDRY_DIE_BINARY`를 지정하면 거부한다. 이전 CLI의 승인된 로컬 fixture와 API 전용 serve는 별도 경로다. [serve](../../../crates/foundry/src/main.rs#L2233) [executor 조립](../../../crates/foundry/src/main.rs#L737)
* 실행 요청은 `POST /api/product/execution`이다. `Authorization: Bearer …`에 원 owner 세션, `X-Foundry-Service`에 현재 DriveReview credential을 제공한다. JSON 공통 필드는 order, lifecycle, admission_hash, request_key, connector, repository_id, api_origin, operation이다. `operation.action=review`는 commit과 selection_revision을 받아 기존 selected-review 조정기를 쓴다. `produce`는 task_sha256과 image를 받아 원 owner의 live task receipt에 결속된 **별도 명시적 실행 결정**을 요구한다. 원 W2 reserve나 poll/watch만으로 이 요청이 발생하지 않는다. 모델 none, 호출/비용/수정 세대 0을 유지한다. 이번 회차에서 이런 실행 결정을 전송하지 않았다. [등록·인증](../../../crates/foundry/src/isolation/dispatch.rs#L45) [리뷰](../../../crates/foundry/src/selected_review.rs#L360) [producer](../../../crates/foundry/src/isolation/dispatch.rs#L132)
* producer 작업 키는 `isolated-produce-v1`, 원 receipt, 이미지, 요청 키의 직렬화에 대한 digest다. 새 예약의 live claim에서 canonical task를 읽고 한 번 실행한다. controller가 isolated collector의 patch digest를 W2 Git seal과 대조한 뒤 ledger collect를 수행한다. 동일 키는 기록된 상태를 반환한다. 실패하면 가능한 경우 uncertain으로 기록한다. 승인·finalizer·실제 작업 이어달리기는 이번 경계에서 수행하지 않았다. [예약 재조회](../../../crates/foundry/src/isolation/dispatch.rs#L170) [canonical 입력](../../../crates/foundry-ledger/src/product/code_change.rs#L574) [seal/collect](../../../crates/foundry/src/isolation/dispatch.rs#L227)
* 원 pack의 최초 redrive 및 일반 stage가 journal과 intent를 launcher로 넘긴다. 같은 경로를 재개 redrive 및 일반 stage에서도 사용한다. 고정된 commit review의 재개는 원 lifecycle의 task kind에서 inspection-only 제한을 복원한다. W2의 offline-only pack/continuation 거부도 적용된다. 원 승인 프로필은 fix 실행권이 없으므로 fixer 라우팅 확인을 실제 W2 fix 실행으로 셀 수 없다. [최초 redrive](../../../crates/foundry-line/src/review_host.rs#L1328) [최초 stage](../../../crates/foundry-line/src/review_host.rs#L1515) [재개 redrive](../../../crates/foundry-line/src/review_host.rs#L2042) [재개 stage](../../../crates/foundry-line/src/review_host.rs#L2225) [원 kind](../../../crates/foundry-ledger/src/product/review.rs#L1927)
* launcher가 등록된 image ID를 확인하고, run마다 controller가 만든 socket inode만 읽기 전용으로 mount한다. child rootfs는 읽기 전용이며 작업은 새 256 MiB tmpfs에서 한다. 주고받는 Git pack은 최대 16 MiB, patch는 최대 4 MiB다. 실행 전 **소유한** 컨테이너의 inspect 값과 이미지 안 worker/client 파일의 SHA-256을 검사한다. 입력/stdout을 제한하고 Docker 로그를 끈다. 종료·실패 시 생성한 ID만 회수한다. 앱이 Git 결과를 받아들이기 전에 회수가 성공해야 한다. 강제 controller 소실 뒤 자동 회수 및 실제 쓰기 중단은 미측정이다. [템플릿](../../../deploy/compose.yaml#L1) [검사·회수](../../../deploy/launcher.py#L56) [Die 및 Git worker](../../../deploy/worker.py#L40)
* 제품 stage 디렉터리에 `render.json`, `binding.json`, `runtime-stage.json`을 쓰도록 구현했다. 생성 stage의 후속 영수증은 `runtime-checks.json`, `runtime-collect.json`, `collected.patch`다. producer의 경로는 artifact root 아래 `w3-producers/<operation-key>/`다. 영수증은 소유 이름, run, render hash, 확인된 환경 값, 회수된 ID를 결합한다. 이번 회차에는 실제 제품 영수증이 없다. [기록 코드](../../../deploy/launcher.py#L90)
* controller는 4바이트 big-endian 길이와 UTF-8 JSON으로 listener를 제공한다. 요청 envelope는 token과 request이며 request에는 run/provider/budget_scope/body만 허용한다. 이미지에 제공하는 `/opt/foundry/model-client`가 stdin body에서 프레임을 만든다. 서버가 고른 upstream AF_UNIX 경로로만 전달하며 `{status, body}` 응답을 검사한다. 실제 모델 키는 child에 제공하지 않는다. W2 제품 생성 경로가 발급하는 권한은 provider none 및 호출 0으로 고정했다. 양성 테스트의 1회 권한은 테스트 생성자 입력이며 제품에 비영 예산을 발급하는 결정은 미승인이다. [grant](../../../crates/foundry/src/isolation/listener.rs#L92) [transport](../../../crates/foundry/src/isolation/listener.rs#L115) [제품 한도](../../../crates/foundry/src/isolation/listener.rs#L157) [클라이언트](../../../deploy/model-client.py#L9)

## 다음 판정의 전제

W30b 판정에는 이 소스 패치와 동결 oracle을 함께 사용한다. Dockerfile의 build context는 `deploy/`다. 승인된 Python/Git/실제 Die가 포함된 digest 고정 base, 빌드된 최종 로컬 이미지, 실제 Die의 manifest 및 model-client 호환성, UID mapping, daemon 접근과 Unix socket 권한은 미검증이다. 이 회차에서 build/pull하거나 다른 컨테이너를 조사하지 않았다. 이미지 또는 허용 설정이 달라지면 해당 지문으로 다시 결속해야 한다. [Dockerfile](../../../deploy/Dockerfile#L1) [런타임 차단 기록](local-runtime.log#L1)
